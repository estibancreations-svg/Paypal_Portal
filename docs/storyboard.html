Part 2 · How it works FLOWS

The four money flows. Dashed boxes are decisions; the line under a decision is the path that leaves the happy route — a hold or a block, always with the reason written into the audit chain.

Flow 1 · In-world purchase + payout split

Passenger picks an item in the world; concierge states the total
↓
Passenger confirms (voice / gaze)?
✕ No → nothing is created; the scene simply continues.
↓
PayPortal creates a PayPal Order; buyer approves in PayPal’s sheet
↓
Capture — then read the capture back from PayPal before calling it paid
↓
Payouts split fires (idempotent batch): cruise line share + local operator share
↓
Receipt shows capture ID + split + points minted against the capture ID

Flow 2 · Agent spend under a mandate

Agent proposes a payment (amount, merchant, purpose)
↓
Signed mandate valid? Signature intact · not revoked · not expired
✕ Fail → BLOCKED with the reason; nothing debits; audit entry written.
↓
Inside scope? Per-purchase cap · daily cap · allowlist · wallet balance
✕ Outside → BLOCKED with the reason. △ Borderline (above everyday threshold) → HELD in the owner approval queue.
↓
Capture under the mandate; read back from PayPal
↓
Ledger + audit entries written; daily spend updated; P&L moves

Flow 3 · Agent earns: held job + Live-mode sweep

Agent completes a job; payment lands as HELD — not earnings yet
↓
Delivery verified by the buyer / platform check?
✕ Not verified → stays HELD; a second verification after release is refused.
↓
Release: earnings credit the agent wallet (EARN ledger entry)
↓
Live mode on and balance above the operating cap?
✕ Live off → earnings stay in the wallet.
↓
Excess sweeps to the owner (SWEEP entry); wallet sits exactly at its cap

Flow 4 · Points lifecycle

A PayPal capture completes on any route
↓
Base mint: 5 points per $10 captured, recorded against the capture ID
↓
Paid through the PayPortal route?
✕ Regular route → base only. ✓ Route → +2 Member / +3 Premium-Enterprise per $10 (daily boost cap; no boost on same-owner internal transfers).
↓
Voyage bonus: +25 per $100 of route spend in a rolling 30 days
↓
Redeem in-system at checkout — never cash out. A refund claws points back proportionally.

Part 3 · How it is set up ARCHITECTURE

Three layers. People and agents only ever touch the top layer; the rules live in the middle; money moves only on PayPal rails at the bottom.

PEOPLE & AGENTS — WHAT THEY TOUCH

WebXR World (ShipWorld)

One URL — Quest Browser, Vision Pro, desktop Chrome. Scene, product cards, concierge, confirm sheet, in-world receipt.

Guardrail Console

Owner’s web app: dashboards, transactions grid, approval queue, audit view, guidelines generator, kill switches.

Judge Mode

One link, pre-loaded sandbox accounts, four guided steps with live PayPal IDs at each step.

AI Agents

Software workers holding wallets. They propose payments and take jobs — they never hold credentials and never own funds.

↓  every action passes through the server — there is no side door  ↓
PAYPORTAL SERVER — THE RULES LIVE HERE

Mandate Engine

Signed mandates: issue, validate (signature · status · expiry · scope), revoke. No valid mandate = no capture.

Wallet Engine

Sub-ledgers, held jobs, Live-mode sweep, per-agent P&L. Agents stop at zero.

Risk Service

Borderline proposals are held for owner approval with a plain-English reason. It can hold — never raise a limit.

Points Engine

Mint-on-capture, route boosts, voyage bonus, clawback on refund, in-system redemption.

Audit Ledger

Append-only hash chain. Every action above writes an entry; verify() names any altered entry.

Guidelines Generator

Plain English → structured draft → owner signs → the mandate engine issues it.

↓  money moves only on PayPal rails  ↓
PAYPAL SANDBOX — THE MONEY

Orders API

Create → approve → capture, with read-backs before anything is called “paid”.

Payouts API

Creator/operator splits and owner sweeps, sent as idempotent batches.

Webhooks

Signature-verified status events reconciled against the ledger.

Identity

Owner sign-in; passkeys guard mandate signing and changes.
